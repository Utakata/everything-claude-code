# トークン最適化ガイド

トークン消費を削減し、セッション品質を延ばし、日々の制限内でより多くの作業を成し遂げるための、実践的な設定と習慣です。

> 関連：モデル選択戦略については `rules/common/performance.md`、自動化されたコンパクション提案については `skills/strategic-compact/` を参照。

---

## 推奨設定

これらはほとんどのユーザーにとっての推奨デフォルトです。パワーユーザーは、ワークロードに基づいて値をさらに調整できます — 例えば、単純なタスクには `MAX_THINKING_TOKENS` を低く、複雑なアーキテクチャ作業には高く設定するなど。

`~/.claude/settings.json` に追加します：

```json
{
  "model": "sonnet",
  "env": {
    "MAX_THINKING_TOKENS": "10000",
    "CLAUDE_CODE_SUBAGENT_MODEL": "haiku"
  }
}
```

### 各設定の効果

| 設定 | デフォルト | 推奨 | 効果 |
|---------|---------|-------------|--------|
| `model` | opus | **sonnet** | Sonnet はコーディングタスクの約80%をうまく処理する。複雑な推論には `/model opus` で Opus に切り替える。約60%のコスト削減。 |
| `MAX_THINKING_TOKENS` | 31,999 | **10,000** | Extended thinking は、内部推論のためにリクエストごとに最大31,999の出力トークンを予約する。これを減らすと隠れたコストを約70%削減する。些細なタスクでは `0` に設定して無効化する。 |
| `CLAUDE_CODE_SUBAGENT_MODEL` | _(メインを継承)_ | **haiku** | サブエージェント（Task ツール）はこのモデルで実行される。Haiku は約80%安価で、探索、ファイル読み取り、テスト実行に十分。 |
| `ECC_CONTEXT_MONITOR_COST_WARNINGS` | on | **サブスクリプションユーザーは off** | コンテキスト枯渇、スコープ、ループの警告を保ちつつ、エージェント向けの API レート推定警告を抑制する。 |

### 自動コンパクションのオーバーライドに関するコミュニティノート

一部の最近の Claude Code ビルドでは、`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` がコンパクションしきい値を下げることしかできないというコミュニティレポートがあり、デフォルトより低い値は後ではなく早くコンパクトする可能性があることを意味します。セットアップでそれが起こる場合は、オーバーライドを削除し、手動の `/compact` と ECC の `strategic-compact` ガイダンスに頼ってください。[トラブルシューティング](./TROUBLESHOOTING.md) を参照。

### Extended thinking の切り替え

- **Alt+T**（Windows/Linux）または **Option+T**（macOS） — オン/オフを切り替え
- **Ctrl+O** — thinking 出力を見る（verbose モード）

## モデル選択

タスクに適したモデルを使用します：

| モデル | 最適な用途 | コスト |
|-------|----------|------|
| **Haiku** | サブエージェントの探索、ファイル読み取り、単純なルックアップ | 最低 |
| **Sonnet** | 日々のコーディング、レビュー、テスト作成、実装 | 中 |
| **Opus** | 複雑なアーキテクチャ、マルチステップの推論、微妙な問題のデバッグ | 最高 |

セッション途中でモデルを切り替えます：

```
/model sonnet     # ほとんどの作業のデフォルト
/model opus       # 複雑な推論
/model haiku      # 素早いルックアップ
```

## コンテキスト管理

### コマンド

| コマンド | 使用するタイミング |
|---------|-------------|
| `/clear` | 無関係なタスクの間。stale なコンテキストは、後続のすべてのメッセージでトークンを浪費する。 |
| `/compact` | 論理的なタスクのブレークポイントで（計画の後、デバッグの後、フォーカスを切り替える前）。 |
| `/cost` | 現在のセッションのトークン支出を確認する。 |

### API レートコスト推定警告

ECC のコンテキストモニターは、ローカルのフックテレメトリから API レートコスト推定を出力できます。Claude サブスクリプションを利用していて、それらの推定が実際の請求を反映しない場合、エージェント向けのコスト警告のみを無効化します：

```bash
export ECC_CONTEXT_MONITOR_COST_WARNINGS=off
```

Windows PowerShell：

```powershell
[Environment]::SetEnvironmentVariable('ECC_CONTEXT_MONITOR_COST_WARNINGS', 'off', 'User')
```

これは、コンテキスト枯渇の警告、スコープ警告、ループ警告、`/cost`、またはコストテレメトリファイルを無効化しません。

### 戦略的コンパクション

`strategic-compact` スキル（`skills/strategic-compact/` 内）は、タスク途中でトリガーされうる自動コンパクションに頼るのではなく、論理的な間隔で `/compact` を提案します。フックのセットアップ手順については、スキルの README を参照してください。

**コンパクトするタイミング：**
- 探索の後、実装の前
- マイルストーンの完了後
- デバッグの後、新しい作業を続ける前
- 大きなコンテキストシフトの前

**コンパクトしないタイミング：**
- 関連する変更の実装途中
- アクティブな問題のデバッグ中
- マルチファイルのリファクタリング中

### サブエージェントはコンテキストを保護する

メインセッションで多くのファイルを読む代わりに、探索にはサブエージェント（Task ツール）を使用します。サブエージェントは20個のファイルを読みますが、サマリーのみを返します — メインのコンテキストはクリーンに保たれます。

## MCP サーバー管理

有効な各 MCP サーバーは、コンテキストウィンドウにツール定義を追加します。README は警告します：**プロジェクトごとに有効なものを10未満に保つ**。

ヒント：
- `/mcp` を実行して、アクティブなサーバーとそのコンテキストコストを見る
- ライブのランタイム変更をしたいときは、`/mcp` を使用して Claude Code の MCP サーバーを無効化する。Claude Code はそれらのランタイム無効化を `~/.claude.json` に永続化する。
- 利用可能な場合は CLI ツールを優先する（GitHub MCP の代わりに `gh`、AWS MCP の代わりに `aws`）
- すでにロードされた Claude Code の MCP サーバーを無効化するために `.claude/settings.json` や `.claude/settings.local.json` に頼らない；それには `/mcp` を使用する。
- `ECC_DISABLED_MCPS` は、`install.sh`、`npx ecc-install`、Codex MCP マージなどの install/sync フロー中の ECC 生成 MCP 設定出力にのみ影響する。ライブの Claude Code トグルではない。
- `memory` MCP サーバーはデフォルトで設定されているが、どのスキル、エージェント、フックからも使用されていない — 無効化を検討する

## Agent Teams コスト警告

[Agent Teams](https://code.claude.com/docs/en/agent-teams)（実験的）は、複数の独立したコンテキストウィンドウを生成します。各チームメイトは別々にトークンを消費します。

- 並列性が明確な価値を追加するタスク（マルチモジュール作業、並列レビュー）にのみ使用する
- 単純なシーケンシャルタスクには、サブエージェント（Task ツール）の方がトークン効率が良い
- 設定で `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効化する

`configure-ecc` インストールウィザードは、セットアップ中にこれらの環境変数を設定するよう提案でき、コストのトレードオフの説明を付けられます。これにより、新規ユーザーが制限に達した後にこれらの設定を発見するのではなく、初日から最適化できるようになります。
