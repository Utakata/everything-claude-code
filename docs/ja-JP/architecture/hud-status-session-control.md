# HUD ステータス・セッション制御契約

この契約は、ECC がローカルオペレーターサーフェス、ハンドオフ、将来の HUD のために使用する、ポータブルなステータスペイロードを定義します。これは意図的にハーネス中立です：Claude Code のステータスライン、Codex ペイン、dmux セッション、OpenCode の実行、またはターミナルのみのワークフローが、フィールド名を変えずに部分的なデータを出力できます。

正規の例は
[`examples/hud-status-contract.json`](../../examples/hud-status-contract.json) にあります。

## ペイロードの形

すべてのステータスペイロードは `schema_version: "ecc.hud-status.v1"` を使用し、以下のトップレベルセクションを安定に保ちます：

| フィールド | 目的 | 主要ソース |
|---|---|---|
| `context` | モデル、ハーネス、リポジトリ、ブランチ、ワークツリー、セッション id、コンテキストウィンドウの圧力 | ステータスライン stdin、git、セッションアダプター |
| `toolCalls` | 最近のツールカウント、保留中の呼び出し、stale な呼び出し、最後のツールイベント | `loop-status`、`tool-usage.jsonl`、フックブリッジ |
| `activeAgents` | 現在のワーカー/サブエージェント、ランタイム状態、ブランチ、ワークツリー、目的、ハンドオフパス | dmux/オーケストレーションのスナップショット |
| `todos` | 現在の進行中タスクと todo のカウント | Claude todos、ローカルタスクファイル、プランメタデータ |
| `checks` | 利用可能な場合の command/check URL を含む、ローカルおよびリモートの検証状態 | CI、ローカルコマンド、リリースゲート |
| `cost` | セッションの支出、トークンカウント、予算、トレンド | コストトラッカー、メトリクスブリッジ |
| `risk` | 注意状態、コンフリクトの圧力、stale な呼び出し、dirty なワークツリー、manual-review フラグ | 準備ゲート、git、キュー状態 |
| `queueState` | GitHub PR/issue/discussion のカウント、コンフリクトキュー、マージキュー、stale-salvage キュー | GitHub 同期、work items |
| `sessionControls` | 現在のターゲットでサポートされるオペレーターアクション | ECC CLI、dmux、git/GitHub |
| `sync` | Linear、GitHub、ハンドオフの公表状態 | ステータス更新、work items、ハンドオフライター |

ハーネスがシグナルを公開できない場合、フィールドは `null`、空の配列、または `"unknown"` にできます。プロデューサーは互換性のない名前を作り出すべきではありません。コンシューマーは、欠けているセクションを green ではなく、利用不可としてレンダリングすべきです。

## セッション制御

最小限のセッション制御ボキャブラリーは以下です：

| 制御 | 意味 |
|---|---|
| `create` | 新しい分離された実行、ワークツリー、またはオーケストレーションプランを開始する |
| `resume` | 既存のセッションまたは履歴上のターゲットに再アタッチする |
| `status` | 状態を変更せずに現在のペイロードを出力する |
| `stop` | 優雅な停止を要求するか、セッションを完了としてマークする |
| `diff` | 現在のワーキングツリーまたはワーカーの差分を表示する |
| `pr` | リンクされたプルリクエストを開くか検査する |
| `mergeQueue` | マージ可能、ブロック済み、チェック待ちの項目を表示する |
| `conflictQueue` | 統合が必要な dirty/コンフリクトする PR またはワークツリーを表示する |

`sessionControls.supported` は、現在のハーネスで利用可能な制御をリストします。`sessionControls.blocked` は、利用できない制御を説明します。例えば、欠けている GitHub トークン、tmux セッションなし、または読み取り専用アダプターなど。

## 同期契約

sync セクションは、耐久性のあるトラッカーを分離します：

- `Linear` は、プロジェクトのステータス更新 id、health、および issue 作成が
  ワークスペースの容量によってブロックされているかどうかを記録します。
- `GitHub` は、現在のリポジトリ、PR/issue/discussion のキューカウント、および
  セッションに紐づいた最新のマージ済みまたはオープンな PR を記録します。
- `handoff` は、耐久性のある Markdown ハンドオフパスと、それが最新のバッチの後に
  書き込まれたかどうかを記録します。

これにより、すべての実行が Linear issue や GitHub コメントを作成することを要求せずに、リアルタイムの進捗追跡が明示的になります。Linear の issue 容量がブロックされている場合でも、ステータスペイロードはプロジェクト更新とリポジトリハンドオフを通じて進捗を証明できます。

## 現在の実装

- `ecc status --json` は、SQLite 状態ストアから準備状況、アクティブなセッション、スキル実行、
  インストールの health、ガバナンス、リンクされた work items を公開します。
- `ecc loop-status --json --write-dir <dir>` は、長時間実行されるループのために、
  ライブのトランスクリプトスナップショットと注意シグナルを書き込みます。
- `ecc session-inspect <target> --write <path>` は、dmux と Claude-history アダプターから
  正規のセッションスナップショットを出力します。
- `scripts/hooks/ecc-statusline.js` は、Claude Code 内でコンパクトなモデル、タスク、コスト、ツール、
  ファイル、期間、ディレクトリ、コンテキスト圧力のシグナルをレンダリングします。

`ecc.hud-status.v1` ペイロードは、ECC が専用のフルスクリーン HUD を持つ前に、これらのサーフェスが投影できる共通の外側の契約です。
