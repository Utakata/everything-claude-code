# プロダクトケイパビリティテンプレート

プロダクトの意図は存在するが、実装の制約がまだ暗黙的な場合にこれを使用します。

目的は、別の曖昧な計画ドキュメントではなく、耐久性のあるケイパビリティ契約を作ることです。

## ケイパビリティ

- **ケイパビリティ名：**
- **ソース：** PRD / issue / discussion / roadmap / 創業者ノート
- **主要アクター：**
- **出荷後の成果：**
- **成功シグナル：**

## プロダクトの意図

ユーザーに見える約束を、1つの短い段落で記述します。

## 制約

実装が始まる前に真でなければならないルールをリストします：

- ビジネスルール
- スコープの境界
- 不変条件
- ロールアウトの制約
- 移行の制約
- 後方互換性の制約
- billing / auth / コンプライアンスの制約

## アクターとサーフェス

- アクター
- UI サーフェス
- API サーフェス
- 自動化 / オペレーターのサーフェス
- レポーティング / ダッシュボードのサーフェス

## 状態と遷移

明示的な状態と許可された遷移の観点でライフサイクルを記述します。

例：

- `draft -> active -> paused -> completed`
- `pending -> approved -> provisioned -> revoked`

## インターフェース契約

- 入力
- 出力
- 必要な副作用
- 失敗状態
- リトライ / リカバリ
- 冪等性の期待

## データへの影響

- 真実のソース
- 新しいエンティティまたはフィールド
- 所有権の境界
- 保持 / 削除の期待

## セキュリティとポリシー

- 信頼境界
- 権限要件
- 悪用パス
- ポリシー / ガバナンスの要件

## 非目標

このケイパビリティが明示的に所有しないものをリストします。

## 未解決の質問

実装をブロックしている未解決の決定をキャプチャします。

## ハンドオフ

- **実装の準備ができているか？**
- **アーキテクチャレビューが必要か？**
- **プロダクトの明確化が必要か？**
- **次の ECC レーン：** `project-flow-ops` / `tdd-workflow` / `verification-loop` / その他
