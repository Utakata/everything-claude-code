# 候補プレイブック：メンテナー所有のstale救済

候補ID：`maintainer-salvage-branch`

## 使用場面

- 公開キューを利用可能に保つため、staleまたはコンフリクトしたPRがクローズされた。
- クローズされた差分に、有用で焦点の絞られたアイデア、スキル、コマンド、ドキュメント、テスト、
  またはバグ修正が含まれている。
- コントリビューターにリベースの時間や関心がない可能性がある。

## 手順

1. ソースPR、作成者、有用なコンセプト、クローズ理由を
   `docs/stale-pr-salvage-ledger.md` に記録する。
2. クローズされたPRの差分を現在の `main` に対して読み直す。
3. パッチを安全にcherry-pickできるか判断する。現在のアーキテクチャが変化している場合は
   再実装を優先する。
4. 焦点を絞った単一の救済ユニットで、メンテナー所有のブランチを作成する。
5. PR本文に、そして有用な場合はコミット本文に、アトリビューションを保持する。
6. 変更対象のサーフェスが必要とするカタログ、ドキュメント、テスト、
   またはリリースエビデンスを更新する。
7. 通常の変更が要求するのと同じ検証ゲートを実行する。
8. マージ後、レジャーを pending/salvage-branch から landed、
   already-present、superseded、skipped、または translator/manual review に更新する。

## 却下条件

- パッチが一括生成されたchurnである。
- パッチがtranslator/manualレビューを必要とするstaleなローカライゼーションである。
- パッチが個人のパス、シークレット、ローカル設定、またはプライベートなオペレーターコンテキストをインポートしている。
- パッチが現在のインストール、カタログ、プラグイン、またはリリースアーキテクチャをバイパスしている。
- ブランチが無関係な救済ユニットを1つのPRに混在させてしまう。

## 最小限の検証

- 変更対象サーフェスに対する的を絞ったテスト。
- `git diff --check`。
- ドキュメントを変更した場合はMarkdown lint。
- スキル、エージェント、コマンド、またはプラグインのサーフェスを変更した場合は
  カタログ/インストール検証。
