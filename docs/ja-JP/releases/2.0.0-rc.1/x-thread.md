# X スレッド草稿 - ECC v2.0.0-rc.1

1/ ECC v2.0.0-rc.1 は、2.0 の方向性に対する最初のリリース候補パスです。

リポジトリは、Claude Code の設定パックから、エージェンティックな作業のためのクロスハーネスなオペレーティングシステムへと移行しています。

2/ 重要な分割：

ECC は再利用可能な基盤（substrate）。
Hermes はその上で動作できるオペレーターシェル。

スキル、フック、MCP 設定、ルール、ワークフローパックは ECC に存在します。

3/ Claude Code は依然としてコアなターゲットです。

Codex、OpenCode、Cursor、Gemini、その他のハーネスも、今や同じストーリーの一部です。

目標は、使い捨てのハーネス小技を減らし、再利用可能なワークフローサーフェスを増やすことです。

4/ v1.10.0 以降、作業はオペレーターレイヤーも取り込みました：

PR/issue/ディスカッション監査、Linear の進捗同期、リリースエビデンス、オブザーバビリティチェック、生成された準備状況ダッシュボード。

5/ セキュリティ姿勢も変わりました。

Mini Shai-Hulud/TanStack キャンペーンは、実際のサプライチェーンループを強いました：

- IOC スキャン
- no-lifecycle な CI インストール
- アドバイザリソースのリフレッシュ
- npm audit/署名チェック
- AI ツールの永続化ターゲット

6/ rc.1 サーフェスは公開部分を出荷します：

- Hermes セットアップガイド
- リリースノート
- ローンチチェックリスト
- クロスハーネスのアーキテクチャドキュメント
- Hermes インポートガイダンス
- プレビューパックのスモークゲート
- X、LinkedIn、記事の草稿

7/ プライベートなワークスペースの状態は出荷しません。

シークレットなし。
OAuth トークンなし。
生のローカルエクスポートなし。
個人データセットなし。

ポイントは、再利用可能なシステムの形を公開することです。

8/ なぜ Hermes が重要なのか：

ほとんどのエージェントシステムは、日々の運用ループで失敗します。

コードは書けても、リサーチ、コンテンツ、ハンドオフ、リマインダー、実行を1つの測定可能なサーフェスに保つことができません。

9/ ECC は再利用可能なレイヤーを提供します。

Hermes はオペレーターシェルを提供します。

両者を合わせると、作業は散らばったチャットウィンドウというより、実行できるシステムのように感じられます。

10/ これはまだリリース候補です。

公開ドキュメントと再利用可能なサーフェスはレビューの準備が整っています。

より深いローカル統合は、サニタイズされるまでローカルに留まり、公開は依然として GitHub リリース、npm、プラグイン、最終 URL のゲートを待っています。
