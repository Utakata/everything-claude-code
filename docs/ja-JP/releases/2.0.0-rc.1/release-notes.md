# ECC v2.0.0-rc.1 リリースノート

## ポジショニング

ECC v2.0.0-rc.1 は、エージェンティックな作業のためのクロスハーネスなオペレーティングシステムとしての ECC にとって、最初のリリース候補サーフェスです。

Claude Code は依然としてコアなターゲットです。Codex、OpenCode、Cursor、Gemini、その他のハーネスは、同じスキル、ルール、MCP 規約、オペレーターワークフローを共有できる実行サーフェスとして扱われます。ECC は再利用可能な基盤であり、Hermes はそのレイヤーの上に位置できるオペレーターシェルとして文書化されています。

## 変更点

- サニタイズ済みの Hermes セットアップガイドを、公開リリースストーリーに追加。
- リリースを1つのレビュー済みサーフェスから出荷できるよう、リポジトリ内にローンチ素材を追加。
- 再利用可能な基盤としての ECC と、オペレーターシェルとしての Hermes の分割を明確化。
- スキル、フック、MCP、ルール、インストラクションのクロスハーネスなポータビリティモデルを文書化。
- ローカルのオペレーターパターンを公開可能な ECC スキルに変換するための Hermes インポートプレイブックを追加。
- BYOK と OpenRouter のシークレットを ECC 管理下のプロジェクトファイルの外に保ちつつ、Zed をプロジェクトローカルな計画/インストールターゲットとして追加。
- コマンドレジストリのカバレッジ、プラットフォーム監査、ディスカッション監査、オペレーターダッシュボード、Linear 進捗準備、プレビューパックのスモークゲートを追加。
- ループステータス、セッショントレース、ハーネス監査、ECC2 のツールリスクログのための、ローカルの [オブザーバビリティ準備ゲート](../../architecture/observability-readiness.md) を追加。
- 2026年5月の Mini Shai-Hulud/TanStack キャンペーンのフォローアップ後、フルキャンペーンの AgentShield IOC カバレッジ、queue-zero/ディスカッションチェック、詳細な Linear ロードマップゲート、5月17日のオペレーターダッシュボードスナップショットを含め、リリース準備エビデンスをリフレッシュ。

  ワークフローのためのクロスハーネス基盤作業；

  デモプロンプト、承認ゲート付きローンチチェックリストのためのローンチ素材。

## なぜこれが重要なのか

ECC はもはや、単なる Claude Code プラグインや設定バンドルではありません。

システムは今、より明確な形を持っています：

- 使い捨てのプロンプトではなく、再利用可能なスキル
- ワークフローの規律のためのフックとテスト
- ドキュメント、コード、ブラウザ自動化、リサーチへの MCP バックエンドのアクセス
- Claude Code、Codex、OpenCode、Cursor、および関連ツールのためのクロスハーネスなインストールサーフェス
- チャット、cron、ハンドオフ、日々の作業ルーティングのための、オプションのオペレーターシェルとしての Hermes

## リリース候補の境界

これはリリース候補であり、最終的な GA の主張ではありません。

このサーフェスで出荷されるもの：

- 公開の Hermes セットアップドキュメント
- リリースノートとローンチ素材
- クロスハーネスのアーキテクチャドキュメント
- サニタイズ済みオペレーターワークフローのための Hermes インポートガイダンス
- キュー状態、ディスカッション状態、Linear ロードマップカバレッジ、オペレーターダッシュボードステータス、サプライチェーンのフォローアップのための公表準備エビデンス
- プライベートな Hermes 状態なしで公開パックが組み立てられることを証明するプレビューパックのスモークエビデンス

ローカルに留まるもの：

- シークレット、OAuth トークン、API キー
- プライベートなワークスペースエクスポート
- 個人データセット
- サニタイズされていないオペレーター固有の自動化
- より深い CRM、財務、Google Workspace のプレイブック

## アップグレードの動き

1. [rc.1 クイックスタート](quickstart.md) に従う。
2. [Hermes セットアップガイド](../../HERMES-SETUP.md) を読む。
3. [クロスハーネスアーキテクチャ](../../architecture/cross-harness.md) をレビューする。
4. [オブザーバビリティ準備ゲート](../../architecture/observability-readiness.md) を実行する。
5. 1つのワークフローレーンから始める：エンジニアリング、リサーチ、コンテンツ、またはアウトリーチ。
6. サニタイズ済みのオペレーターパターンのみを ECC スキルにインポートする。
7. リリースパッケージングとインストーラーの挙動が最終化されるまで、`ecc2/` をアルファのコントロールプレーンとして扱う。

## まだ公開済みとして扱わないこと

リリース候補のコピーは最終レビューの準備が整っていますが、公開リリースは依然として承認ゲート付きのアクションでブロックされています：GitHub プレリリース、npm `next`
publish、Claude プラグインのタグ/marketplace パス、Codex Plugin Directory のステータス、
最終的なライブ URL、および billing や native-payments のアナウンス。
