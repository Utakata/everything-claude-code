# LinkedIn草稿 - ECC v2.0.0-rc.1

ECC v2.0.0-rc.1 は、2.0 の方向性に対する最初のリリース候補（release-candidate）パスとして、最終リリースレビューの準備が整いました。

実務上の変化はシンプルです：ECC はもはや、単なる Claude Code プラグインや設定バンドルとして位置づけられていません。

エージェンティックな作業のための、クロスハーネスなオペレーティングシステムになりつつあります：

- 使い捨てのプロンプトではなく、再利用可能なスキル
- 手作業の規律ではなく、フックとテスト
- ドキュメント、コード、ブラウザ自動化、リサーチへの MCP バックエンドのアクセス
- Codex、OpenCode、Cursor、Gemini、Zed、Claude Code の各サーフェスが、同じコアワークフローレイヤーを共有
- チャット、cron、ハンドオフ、日々の作業ルーティングのためのオペレーターシェルとしての Hermes

このリリース候補サーフェスについては、リポジトリを正直に保ちました。

プライベートなワークスペースの状態は公開していません。再利用可能なレイヤーを出荷しました：

- サニタイズ済みの Hermes セットアップドキュメント
- リリースノートとローンチ用素材
- クロスハーネスのアーキテクチャノート
- ローカルのオペレーターパターンを公開 ECC スキルに変換するための Hermes インポートガイダンス
- PR、issue、ディスカッション、Linear の進捗、レガシーの残務、オブザーバビリティ、サプライチェーンチェックのためのリリース準備ゲート
- リリースアクションの前に公開パックを検証できる、決定論的なプレビューパックのスモークテスト

レバレッジは、単により良いプロンプティングだけではありません。

分離されたサーフェスの数を減らし、繰り返されるワークフローを再利用可能なスキルに変え、エージェントを取り巻くオペレーティングシステムを測定可能にすることです。

サプライチェーンの作業も、リリースストーリーの一部になりました。Mini
Shai-Hulud/TanStack キャンペーンの後、rc.1 には IOC スキャン、no-lifecycle な CI
インストール、アドバイザリソースのリフレッシュ、npm audit/署名チェック、および AI ツールの
永続化カバレッジが含まれるようになりました。

GA の前に、特にパッケージング、インストーラー、`ecc2/` コントロールプレーンの周辺で、まだハードニングすべきことが残っています。しかし rc.1 は、その形を明確に示すには十分です。

公開の公表は、GitHub リリース、npm `next` publish、プラグインパス、最終 URL、および
billing/native-payments の主張にライブのエビデンスが揃うまで、承認ゲートのままです。
