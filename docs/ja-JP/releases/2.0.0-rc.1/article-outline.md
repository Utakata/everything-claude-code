# 記事アウトライン - ECC v2.0.0-rc.1

## 仮タイトル

ECC をクロスハーネスなオペレーティングシステムに変える

## 中心的な主張

ほとんどのエージェンティックな作業は、ツールが分離されたままであることが原因で破綻します。

レバレッジは、ハーネス、再利用可能なワークフローレイヤー、オペレーターシェルを1つのシステムとして扱うことから生まれます：

- 繰り返し可能な作業のためのスキル
- 強制のためのフックとテスト
- ツールアクセスのための MCP
- 継続性のためのメモリとハンドオフ
- 日々の実行をルーティングできる1つのオペレーターシェル

## 構成

### 1. 問題

- チャットウィンドウが多すぎる
- ツール固有のワークフローが多すぎる
- 再利用可能なシステムの形ではなく、個人の習慣の中に生きているコンテキストが多すぎる

### 2. ECC がすでに解決したこと

- 再利用可能なスキル形式
- クロスハーネスのインストールサーフェス
- フックと検証の規律
- セキュリティとレビューのパターン
- コンテンツ、リサーチ、ビジネスオペレーションを取り巻くオペレーターワークフローのスキル
- 運用状態を検査可能にする、キュー、ディスカッション、Linear、レガシー、リリースエビデンスの
  チェック
- Mini Shai-Hulud/TanStack キャンペーン後の、サプライチェーン IOC スキャンと
  no-lifecycle インストールのハードニング

### 3. なぜ Hermes がオペレーターレイヤーなのか

- チャット、CLI、TUI、cron、ハンドオフが、再利用可能な ECC レイヤーの上に位置できる
- ビジネスとコンテンツの作業が、エンジニアリングの作業の隣で実行できる
- 日々のループが検査・改善しやすくなる

### 4. rc.1 で出荷されるもの

- サニタイズ済みの Hermes セットアップガイド
- リリースと配信用の素材
- クロスハーネスのアーキテクチャドキュメント
- Hermes インポートガイダンス
- リポジトリ内でのより明確な 2.0 のポジショニング
- プレビューパックのスモークゲート
- GitHub リリースコピー、X、LinkedIn、記事、Telegram/Hermes
  ハンドオフ、デモプロンプトのためのローンチ草稿

### 5. v1.10.0 以降の変更点

- Claude Code は依然としてコアなターゲットですが、ECC は現在 Codex、OpenCode、
  Cursor、Gemini、Zed、ターミナルのみのワークフローを、共有の実行サーフェスとして扱います。
- リリースプロセスには、繰り返し可能なプラットフォーム、ディスカッション、オブザーバビリティ、
  サプライチェーン、Linear の進捗、プレビューパックのチェックが加わりました。
- AgentShield と ECC Tools の作業はロードマップにミラーされ、エンタープライズの
  セキュリティ、ホステッドレビュー、ポリシー昇格、billing-readiness のレーンがメインリリースから
  ドリフトしないようになっています。

### 6. ローカルに留まるもの

- シークレットと認証
- 生のワークスペースエクスポート
- 個人データセット
- サニタイズされていないオペレーター固有の自動化
- より深い CRM、財務、Google Workspace のプレイブック

### 7. 締めのポイント

目標は、1つの正確なスタックをコピーすることではありません。

目標は、繰り返される作業を再利用可能で測定可能なサーフェスに変える、エージェントを取り巻くオペレーティングシステムを構築することです。
