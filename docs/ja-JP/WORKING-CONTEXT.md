## 目的

- 主なアクティブな運用作業:
  - デフォルトブランチをグリーンに保つ
  - パブリックの PR バックログがゼロになったため、`main` からのイシュー駆動の修正を継続する

## 現在の制約

- タイトルやコミットサマリーのみでのマージは不可。
- 出荷される ECC 表面に任意の外部ランタイムのインストールを含めない。
- 重複するスキル、フック、エージェントは、重複が大きくランタイムの分離が必要ない場合、統合すること。

## アクティブなキュー

- PRバックログ: 減少していますがアクティブです。安全な ECC ネイティブの変更のみを直接移植し、重複、古いジェネレーター、未監査の外部ランタイムレーンを閉じることを継続します
- アップストリームのブランチバックログは、依然として選択的なマイニングとクリーンアップが必要です:
  - `origin/feat/hermes-generated-ops-skills` にはまだ3つのユニークなコミットがありますが、再利用可能な ECC ネイティブのスキルのみをそこからサルベージすべきです
  - 複数の `origin/ecc-tools/*` 自動化ブランチは古くなっており、固有の価値を持たないことを確認した後に削除すべきです
- プロダクト:
  - 選択的インストールのクリーンアップ
  - コントロールプレーンのプリミティブ
  - オペレーター表面
  - 自己改善スキル
  - `agent.yaml` のエクスポートパリティを、出荷される `commands/` と `skills/` ディレクトリと一致させ、最新のインストール表面がコマンド登録を静かに失わないようにする
- スキルの品質:
  - コンテンツ関連のスキルをソースに基づく音声モデリングを使用するように書き換える
  - 一般的な LLM の修辞、定型的な CTA パターン、強制的なプラットフォームのステレオタイプを削除する
  - 重複する、またはシグナルの低いスキルコンテンツの1つずつの監査を継続する
  - リポジトリのガイダンスとコントリビューションフローをスキルファーストに移行し、コマンドは明示的な互換性シムとしてのみ残す
  - 生の API や切断されたプリミティブのみを公開するのではなく、接続された表面をラップするオペレータースキルを追加する
  - 標準的な音声システム、ネットワーク最適化レーン、再利用可能な Manim 説明レーンを着地させる
- セキュリティ:
  - 依存関係の姿勢をクリーンに保つ
  - 自己完結型のフックと MCP の動作を維持する
